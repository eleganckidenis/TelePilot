# TelePilot 2.1.0 audit

Baseline: public v2.0.3, commit f6eac92621f24a811354f8713a67db2c61355832.
Scope: Windows x64, Windows ARM64 and native macOS Apple Silicon. Tests use
synthetic media, local HTTP services and isolated preferences, keys and scheduled
jobs. Private provider accounts and the user's saved profile are excluded.

## Published behavior corrected

- EOF previously entered recovery for some live/TS streams, and terminal recovery
  did not consistently close the player and restore channel-list focus.
- `Playing`/wall-time-based resets could replenish retries without sustained
  successful output. Failed connections now share one bounded six-retry budget.
- The initial cache and watchdog allowances disagreed with the configured target.
  Automatic cache now tracks the actual applied value separately from its target.
- Windows could discard a recovery decision generated by a synthetic `Playing`
  sample, leaving pending recovery without scheduled work.
- macOS asynchronous archive seeks and track dialogs could outlive the native
  input they belonged to. Session and attempt checks now reject stale operations.
- Track restoration on macOS now matches unique names as well as identifiers,
  accommodating identifiers that change when an input is reopened.

## Independent review and regression coverage

A focused independent review used **gpt-6-astra with high reasoning**, including
the old public implementation and the complete replacement diff. Findings in the
new implementation were fixed before publication: discontinuity/refill false
alarms, unhealthy budget resets, signed/unavailable counter handling, first-frame
watch timing, stale terminal UI callbacks, cancellation on alternative play
routes, and terminal volume/mute updates. These prepublication findings are not
all defects in v2.0.3.

The 32 deterministic cross-platform traces (2,422 steps) cover EOF in live/archive/pending/paused
states; all six retries; stable sparse/frequent polling; starvation versus output
freeze; repeated buffering; actual versus desired cache; pause, seek and tracks;
counter resets/negative values; missing stats; invalid time; observation gaps;
first-video-output waits; and the absolute no-progress deadline. Both runners
export actual decisions and all policy state for a step-by-step parity check.
All exported decision/state rows match between platforms, with floating-point
tolerance of 0.000001 seconds. The trace file is executable evidence, not just a
list of intended outcomes.

Native tests additionally exercise finite HTTP EOF, failure retries, keyboard
focus and selected-channel restoration, late operations, recording, EPG,
preferences and platform scheduling. macOS LibVLC/AppKit integration tests run
serially: simultaneous independent native test players can crash the pinned
VLC decoder plugin, while the application owns one player. The tests retain real
playback rather than replacing it with mocks.

Final platform counts, exact Windows CI run, packaged-app checks and anonymous
public download verification are recorded in the GitHub release description.
The release verifier checks installer/source assets, SHA-256 files, GitHub digest
metadata, commit correspondence, architectures and dependency/source links.

## Distribution and verification limits

VLC 3.0.24, LibVLCSharp and the FFmpeg dependency versions are unchanged. Their
matching source bundles and notices remain available; the shared VLC archive is
the pinned v2.0.1 asset with SHA-256
800818898a94ce8ebaa5bfbbbe1246251ca19ef990e735b60ae26d1ab0e8df93.
macOS is signed ad hoc without Apple notarization; Windows installers are unsigned.

Automated keyboard/accessibility-tree checks do not establish audible VoiceOver,
NVDA or Narrator behavior. No private IPTV-provider test or guarantee of zero
remaining defects is claimed. The [policy document](ADAPTIVE_BUFFERING.md) explains
the measurements and limits of stall detection.
