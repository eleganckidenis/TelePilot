# Audyt TelePilot — 10 września 2026

Poprawki dotyczą kodu projektu na bazie 2.0.1. Nie stanowią nowego wydania ani
aktualizacji aplikacji zainstalowanej w Program Files.

## Naprawione problemy

| Obszar | Błąd i poprawka |
|---|---|
| Lista kanałów | Każda litera uruchamiała niezależny skok. Wpisywany tekst jest teraz łączony w prefiks, np. `p → po → pol`. Dopisywanie zachowuje bieżący kanał, jeśli nadal pasuje. |
| Znaki i korekta | Obsługa tekstu uwzględnia układ klawiatury, wielkie litery, AltGr, polskie znaki, cyfry i spacje. Backspace usuwa znak, Escape i przerwa 2 sekund rozpoczynają nowy wpis. Powtarzanie jednej litery nadal przechodzi cyklicznie przez dopasowania. |
| Fokus listy | Odroczone ustawienie fokusu nie cofa Tab ani świadomego przejścia do menu, innego okna lub kontrolki. Uwzględnia również utratę kontenera podczas przewijania długiej listy. Zachowano standardowy ListBox i SelectionItem. |
| Odtwarzanie po wyszukiwaniu | Enter tuż po przejściu Tabem na wynik pozostawiał odtwarzacz bez fokusu na czas ochrony poprzedniego Taba. Jawne żądanie nowej akcji znosi to opóźnienie. Zdarzenia Connecting/Playing nie anulują oczekującego przeniesienia fokusu. |
| Weryfikacja fokusu | Odłączony wiersz listy i korzeń okna nie są już uznawane za bezpieczną kontrolkę. Gdy VLC przejmie fokus Windows, ponowne jawne żądanie aktywnej kontrolki również odświeża zdarzenie UIA. Prawidłowy fokus nie generuje dodatkowych zdarzeń. |
| Szybkie przełączanie i Tab | Tab i Shift+Tab weryfikują fokus po zakończeniu nawigacji, bez oczekiwania na stale odsuwany okres ochronny. Zmiany wyjścia wideo VLC niezależnie zlecają weryfikację. Zachowana jest kontrolka wybrana przez użytkownika i aktualny widok, a stare stany odtwarzania nie ponawiają żądań fokusu. |
| Ctrl+L | Skrót pokazuje i ukrywa listę podczas odtwarzania. Ukrycie kieruje fokus na kontrolki bez restartu obrazu. Nowsze pokazanie listy podczas łączenia nie jest nadpisywane przez kończące się otwieranie odtwarzacza. |
| Wczytywanie playlisty | Stara, anulowana operacja mogła opublikować kanały lub wyłączyć stan wczytywania nowszej. Wynik jest sprawdzany po oczekiwaniu, a kanały publikowane dopiero po zakończeniu pracy. |
| EPG | Audycja bez `stop`, rozpoczęta przed północą, znikała z programu następnego dnia. Granica następnej audycji jest teraz uwzględniana tak samo jak przy ustalaniu bieżącego programu. |
| Nagrywanie | Odrzucone drugie Start mogło zakończyć zadanie oczekujące na aktywne nagranie. Błąd walidacji drugiego startu nie zmienia aktywnej sesji. |
| Zdarzenia FFmpeg | Szybkie zakończenie procesu i spóźnione zdarzenie starej sesji mogły zmienić stan nowego nagrania. Obsługa końca jest synchronizowana ze Start/Stop i sprawdza tożsamość procesu. Nie emituje drugi raz stanu końcowego. |
| Zatrzymanie FFmpeg | Stop ogłaszał sukces również po błędzie procesu. Teraz zachowuje rzeczywisty wynik, obsługuje zamknięte stdin i obejmuje limitem czasu także zapis polecenia zatrzymania. Nieudany start zwalnia obiekt procesu. Odczyt wyjścia używa ograniczonego bufora. |
| Pliki nagrań | FFmpeg używał `-y` mimo wcześniejszego wyboru wolnej nazwy. Teraz `-n` chroni plik utworzony w międzyczasie przez inne nagranie. |
| Harmonogram Windows | Deklaracja XML wskazywała UTF-16, a zapis używał UTF-8. Kodowanie pliku zgadza się teraz z deklaracją. Anulowanie oczekiwania na koniec nagrania nie jest traktowane jako osiągnięcie zaplanowanej godziny. |
| Wspólny harmonogram | Osobne procesy mogły nadpisać zmiany innych nagrań podczas odczytu i zapisu JSON. Blokada pliku obejmuje całą operację odczyt–zmiana–zapis; oczekiwanie można anulować. |
| Ustawienia | Element `null` w ulubionych przerywał wczytywanie preferencji. Jest pomijany przy normalizacji. |

## Próba z NVDA

Nie wykonano odsłuchu z rzeczywistym NVDA ani kontroli natywnego drzewa UIA w tej
sesji. Dostępne narzędzia nie udostępniają sterowania pulpitem Windows. Wyniki
headless potwierdzają logikę i kontrakty kontrolek, ale nie zastępują tej próby.

1. Zamknij działający TelePilot, aby mechanizm pojedynczej instancji nie
   przekierował uruchomienia do poprzedniej wersji.
2. Uruchom `.artifacts/audit-2026-09-10/Uruchom-TelePilot-test.cmd` w tym projekcie.
   Skrót korzysta z istniejącego lokalnego SDK i poprawionej kompilacji Debug;
   odtwarzacz korzysta ze zwykłych danych aplikacji.
3. Na liście wpisz `p`, następnie `o`, następnie `l`, z przerwami krótszymi
   niż 2 sekundy. Sprawdź zaznaczenie i odczyt, powtarzanie `p`, Backspace,
   Escape, `TVP 2` oraz skok do kanału poza widoczną częścią listy.
4. Wpisz prefiks i natychmiast naciśnij Tab; fokus ma pozostać poza listą.
5. Odtwórz kanał Enterem, zatrzymaj Ctrl+S, wybierz inny, naciśnij Enter i Tab.
   Sprawdź odczyt przycisków i responsywność drugiego odtwarzacza.
6. Wyszukaj `fokus` lub `polsat sport 1`, aby pozostał jeden wynik. Przejdź
   Tabem przez grupę na wynik i od razu naciśnij Enter, następnie Tab oraz
   Shift+Tab. Sprawdź odczyt kontrolek NVDA także po Ctrl+S i ponownym Enterze.
   Powtórz z kilkoma wynikami `polsat`, wybierając inny kanał po zatrzymaniu.
7. Wykonaj serię 20 szybkich PgUp/PgDown, także podczas łączenia, a następnie
   Tab i Shift+Tab. Sprawdź odczyt kontrolek również po opóźnionym pojawieniu
   się obrazu. Naciśnij kilka razy Ctrl+L: lista ma pojawiać się i znikać,
   fokus ma przechodzić między kanałem a kontrolkami, a transmisja ma trwać.

Pełny scenariusz znajduje się w `ACCESSIBILITY_TEST_CHECKLIST.md`.
macOS, VoiceOver, podpisywanie i instalator nie były przedmiotem tego wydania
poprawek. Nie zmieniono numeru wersji ani instalacji systemowej.
